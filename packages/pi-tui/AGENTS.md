# pi-tui Agent Guide

`packages/pi-tui` is a vendored copy of pi-tui from the upstream pi-mono project (baseline: upstream 0.80.2, see commit `7859b0af`). It is no longer patched via pnpm patches — all local fixes are applied directly to the source. The differential-rendering behavior in `src/tui.ts` matches upstream: the fork's viewport/scrollback rendering patches were reverted; the only remaining divergences are listed below.

## Local divergences from upstream (must be preserved on every re-vendor)

Never overwrite this directory wholesale when syncing from upstream. Each of the following local fixes must be re-verified after a sync; all of them are guarded by tests:

1. **`src/components/editor.ts` — `wordWrapLine` single-grapheme recursion guard**: when a segment cannot be split further (a single grapheme) and is wider than `maxWidth`, do not recurse (upstream recurses infinitely and overflows the stack at maxWidth=1 with CJK). The guard must be based on grapheme count (`graphemeSegmenter.segment(...)`), not code-unit length — `grapheme.length` misjudges ZWJ emoji. Guarding tests: "wordWrapLine narrow width" and "Editor narrow width rendering" in `test/editor.test.ts`.
2. **`src/tui.ts` — `Container.render` width clamp**: `width = Math.max(1, width)` at the entry point. Guarding test: "Container width clamping" in `test/tui-render.test.ts`.
3. **`src/tui.ts` — truncate overwide lines instead of throwing**: `doRender` truncates overwide lines with `sliceByColumn` while building the per-line processed output (upstream had a "write crash log + throw" block in the differential render path — do not bring it back when syncing). Performance constraint: the width check must go through the `asciiVisibleWidth` fast path in `utils.ts` first (ANSI-aware ASCII scan with an early exit past the limit) and only fall back to `visibleWidth` for non-ASCII lines; `WIDTH_CACHE_SIZE` is 4096 to match. Since divergence 5 below, this check only runs for lines whose raw string reference changed since the previous frame, so the every-line-every-frame scan (and its width-cache FIFO thrash beyond 4096 distinct non-ASCII lines) no longer occurs. Guarding tests: "TUI overwide line handling" in `test/tui-render.test.ts` (exact viewport assertions) and "asciiVisibleWidth" in `test/truncate-to-width.test.ts`.
4. **`src/components/text.ts` / `markdown.ts` / `truncated-text.ts` / `editor.ts` — negative-width `repeat` guards**: the `repeat` counts for blank lines, horizontal rules, and the editor's top/bottom borders are clamped to ≥ 0 (two editor border sites; markdown's emptyLine and hr — the hr site is currently unreachable from the render entry and is purely defensive). Guarding tests: the "negative width safety" cases — Text's lives in `test/tui-render.test.ts` (Text has no dedicated test file), Markdown's and TruncatedText's live in their own test files; the editor's is "does not throw at zero or negative widths" inside the "Editor narrow width rendering" group in `test/editor.test.ts`.
5. **`src/tui.ts` — per-frame processed-line reuse**: `doRender` keeps the previous frame's raw lines (`previousRawLines`), their processed output (`previousLines`), and per-line kitty image ids (`previousLineImageIds`). A line whose raw string is reference-identical to the previous frame's reuses its processed output (truncation + `normalizeTerminalOutput` + trailing `SEGMENT_RESET`) verbatim, so a steady-state frame costs O(total lines) pointer comparisons plus O(changed lines) real work instead of re-normalizing every line. Image-id consumers (`expandChangedRangeForKittyImages`, `deleteChangedKittyImages`, the frame-end id union) read the cached per-line ids rather than re-scanning line text; upstream has no such cache and re-processes every line every frame (upstream also has `applyLineResets`, which this divergence inlines into the processed-line build). Reuse is only valid when the terminal width is unchanged; width changes re-render everything at the new width so references never match. Guarding tests: "TUI steady-frame processed-line reuse" in `test/tui-render.test.ts`.
6. **`src/tui.ts` / `src/ledger/engine.ts` — external-output resync boundary**: after a caller writes visible output directly to the terminal, it must call `TUI.notifyExternalOutput()`. The next ledger frame uses an absolute full paint without `ED3`, restoring cursor/ledger agreement while preserving scrollback. Raw streams are not intercepted automatically. Guarding test: "resynchronizes the ledger after notified external output" in `test/ledger-engine-golden.test.ts`.

7. **`src/ledger/engine.ts` — `ED3` only on geometry rebuild**: the `fullPaint` render intent computes `clearScrollback` from `geometryRebuild` alone, not from `replaceRequested || geometryRebuild` (upstream clears scrollback on any forced repaint). `ED3` (`\x1b[3J`) erases saved lines, so upstream destroys whatever history the user had scrolled back to read whenever `requestRender(true)` runs at unchanged geometry — a reflow genuinely invalidates the saved lines, an ordinary forced repaint does not. The `!isMultiplexerSession()` guard is kept even though `geometryRebuild` already implies it (it requires `!resizeRepaintsInPlace()`, which subsumes the multiplexer check), so the intent stays explicit if either predicate is later redefined. Guarding test: "clears scrollback only on geometry rebuild, not on later forced repaints" in `test/ledger-engine-golden.test.ts`; it asserts both directions and forces the non-multiplexer path via a `withoutMultiplexer` env helper, because both predicates read `process.env` at call time and the branch is skipped entirely inside tmux.

8. **`src/ledger/engine.ts` — in-place repaint for short frames**: when a full paint is requested by the TUI itself and the whole frame already sits on screen at `windowTop === 0` with `contentRows < height`, `#emitFullPaint` takes a `rewriteInPlace` branch: it moves back up to its own first row, rewrites exactly `contentRows` rows via `#lineRewriteSequence`, and writes neither the padding rows nor `\x1b[2J`. Upstream always erases the screen and repaints from the absolute home, which wipes whatever the terminal held below our rows and leaves an empty band under the input line — the "bottom of the screen went blank after a repaint" report. The guard is deliberately narrow: `firstPaint`, `geometryRebuild`, and `#fullPaintOnNextRender` (external output) all still take the absolute repaint, because the invariant this branch relies on — `window[0]` is at screen row 0, which makes `#hardwareCursorRow` equal the screen row — is itself established by `2J`+`H`, and external output can scroll it out from under us. Do not widen the condition without giving the ledger a real screen-row anchor. Guarding test: "rewrites a short frame in place instead of erasing the screen" in `test/ledger-engine-golden.test.ts`; "pads a short frame to full height and parks the cursor at the content bottom" pins the absolute path that first paint still takes.

9. **`src/index.ts` — `wordWrapLine` / `TextChunk` are exported**: upstream keeps both internal to `components/editor.ts`. `apps/kimi-code` maps mouse clicks back to a cursor position and must resolve soft wrapping through the *same* function the editor renders with — a second wrapping implementation drifts from the rendered layout and puts the cursor on the wrong character, especially with CJK and ZWJ emoji. `TextChunk.startIndex` is what makes the reverse lookup exact. No behaviour change, but the export must be restored on every re-vendor or `apps/kimi-code/src/tui/utils/editor-mouse-position.ts` stops compiling. Guarding test: "locateEditorCursor" in `apps/kimi-code/test/tui/editor-mouse-position.test.ts` (outside this package, so `pnpm --filter @moonshot-ai/pi-tui test` will not catch its loss — the app typecheck will).
10. **`src/tui.ts` / `src/ledger/engine.ts` — opt-in fullscreen virtual surface**: `TUIOptions.fullscreen` owns a symmetric `?1049h`/`?1049l` lifetime and always forces the ledger engine; `PI_TUI_ENGINE=legacy` remains available only to normal-screen callers and must never create a fullscreen managed-mouse/native-scrollback hybrid. Fullscreen paints exactly one viewport and never replays the frame prefix into native scrollback; wheel scrolling and scrollbar dragging share the ledger's absolute `{offset,maxOffset}` state. Overlay composition reads a temporary scroll state derived from the frame currently being painted, not the previous committed frame, so scrollbar geometry does not lag after append or resize. Guarding tests: "owns a fullscreen alternate-screen lifetime", "forces the ledger engine for fullscreen even when legacy is requested", "repaints a scrolled fullscreen window without re-emitting frame history", "composites scrollbar overlays with the frame geometry being painted", and the 100-update wheel/scrollbar stress case in `test/ledger-engine-golden.test.ts`.
11. **`src/tui.ts` / `src/ledger/engine.ts` / `src/utils.ts` — app-owned transcript selection**: selection anchor/focus live in frame coordinates and map through the current virtual viewport, including pinned bottom rows. Edge autoscroll updates the virtual viewport and selection focus atomically against the resulting window, allowing a held drag to cross multiple viewports without stale screen-to-frame mapping. ANSI styling is preserved while highlights and copied text respect complete CJK/ZWJ graphemes; SGR `0`/`27` inside selected text reapply inverse highlighting. Guarding tests: "selects and highlights fullscreen frame text across ANSI, CJK, ZWJ and rows", "atomically extends a selection across multiple fullscreen viewports", and `test/text-selection-utils.test.ts`.
12. **`src/ledger/engine.ts` — one visible cursor in hardware mode**: focused inputs still emit their marker and reverse-video fallback, but frame ingestion removes only the marker-adjacent reverse-video opener when the real terminal cursor is enabled. Text and the component's reset sequence remain intact; software-cursor mode is unchanged. Changing cursor mode invalidates composed-frame caches. Guarding test: "renders exactly one cursor in hardware and software modes" in `test/ledger-engine-golden.test.ts`.
13. **`src/terminal.ts` / `src/terminal-probe.ts` / `src/tui.ts` — restart-safe capability probes**: stopping or restarting `ProcessTerminal` aborts the active startup probe, synchronously removes its raw-stdin observer, clears its timers, and invalidates its generation. Only the current `probeReady` may apply capabilities or trigger a ledger refresh; an external-editor suspend/resume must never leave two probe FIFOs consuming the same DA1 replies. Guarding test: "aborts promptly, unsubscribes, and ignores later replies" in `test/terminal-probe.test.ts`.

## Acceptance after syncing from upstream

- `pnpm --filter @moonshot-ai/pi-tui test` must pass in full; any failure among the guarding tests above means a local divergence was overwritten and lost.

## Testing

- This package's tests run with `node --test` (`pnpm --filter @moonshot-ai/pi-tui test`), not vitest; the root `vitest run` does not execute them — CI covers them through the dedicated `test-pi-tui` job in `.github/workflows/ci.yml`.
- Prefer adding new narrow-width tests to the existing test file of the corresponding component.
